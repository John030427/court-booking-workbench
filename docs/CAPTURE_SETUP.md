# 账号接入与自动恢复

> 公开版准备文档。配套通用化代码和脚本尚未发布，不要直接照此修改网络。本文用于说明验收流程，不保证所有预约平台或代理客户端兼容。

## 先选方式

- 不愿修改代理或证书：优先考察页面脚本。前提是官方页面允许打开开发工具，并且连接脚本支持当前平台。
- 希望在登录失效时自动接收新登录信息：可以评估本机采集方案。必须是本人账号、本人设备，并确认预约平台允许相关操作。
- 代理软件不能针对单一域名分流：不要强行改全局设置。用页面方案，或先让维护者检查兼容性。

自动恢复的实际过程是：检测鉴权失败，暂停相关请求，在已登录的官方页面触发受控刷新，接收新登录信息，再只读复验。它不是生成凭证、延长平台有效期，也不能绕过重新登录或人工验证。

## 配置前只读检查

1. 确认本机工作台已启动，且没有需要保护的运行中任务。
2. 确认 8766 是工作台、8080 是本机采集代理。若端口被其他程序占用，停止配置，不结束占用者。
3. 明确自己使用的代理客户端、是否开启 TUN、规则模式以及当前分流方式。
4. 从本人官方页面确认预约站点地址，只在本机填写，不提交到公开仓库或 Issue。
5. 检查该平台是否有经过验证的适配。仅改变域名不能保证接口与登录捕获兼容。

## 配置脚本应该做什么

公开版配套脚本需要通过以下验收后才能发布为「一键配置」：

- 先显示检查结果，每项修改前说明影响、备份位置和撤销办法，并征得使用者同意。
- 只让明确指定的预约站点经过本机采集代理；不扩大到整个组织域名、所有 HTTPS 或所有浏览器流量。
- 保留原有代理规则、节点、DNS 和订阅，不未经许可切换模式或开关 TUN。
- 防止工作台及采集进程向预约站点发出的请求再次回到自身；其他流量走向不变。
- 证书只能使用本机生成的证书，经同意安装到当前用户；不分发证书私钥，不关闭 TLS 校验来掩盖配置错误。
- 不启动预约任务、不修改测试模式或身份信息、不发送测试订单、不清空订单记录。

脚本无法识别客户端配置或发现重复规则时应停止，不能以整份替换配置的方式继续。

## 完成后如何确认

1. 使用者本人打开官方预约页并正常登录。
2. 查看工作台的连接状态、最近同步时间及验证时间，不输出登录值或预览片段。
3. 如需平台只读验证，先明确取得同意。只读验证不会下单，但会访问预约平台。
4. 明确告知哪些已实测、哪些尚未验证。需要人工登录时按提示处理。

一次同步成功不代表以后一定能自动恢复。是否可自动刷新需要在无真实预约任务的情况下另行验证，不能拿放号中的任务做试验。

## 撤销

只撤销本工具添加且能够准确识别的规则、配置和证书。删除证书前核对指纹及其他工具是否依赖它，不按模糊名称批量删除。

若预约页突然无法打开，先检查本机代理是否退出以及是否仍残留分流规则。不要为排障关闭整个 VPN 或覆盖原有配置。

需要本地 AI 协助时，使用 [配置提示词](LOCAL_AGENT_CAPTURE_PROMPT.md)。
