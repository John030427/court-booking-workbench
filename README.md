# Court Booking Workbench

场地预约工作台：提前安排定时抢场，或持续关注退订后出现的空场。

> **发布准备中。** 当前目录是公开版文档草稿，尚未附带可运行源码、安装包或完整教学视频。不要把这些文档当成已发布的软件。上线前检查见 [发布清单](docs/RELEASE_CHECKLIST.md)。

## 先了解这几点

- 程序运行在自己的 Windows 电脑上，浏览器是操作面板，不是云端托管服务。
- 仅使用自己的合法账号，并遵守预约平台规则。工具不保证抢到场地，不绕过登录或预约权限。
- 本项目基于特定预约流程开发，**不是填入任意网站地址就能使用的通用预约器**。公开版的平台配置与兼容性还需要验证。
- 不要分享个人配置、Token、Cookie、订单记录、原始日志或证书私钥。
- 现有版本默认真实预约。第一次使用先检查「设置 → 测试模式」，需要演练时开启测试模式。监控中的「只提醒我」与全局测试模式不是同一个开关。

## 选择使用方式

| 你想做什么 | 使用功能 | 关键设置 |
| --- | --- | --- |
| 提前设定，在放号时尝试预约 | 定时抢场 | 使用日期、时段、候选场地、放号日期与时间 |
| 等待别人取消，出现空场时通知 | 持续监控 | 日期、搜索时段、预约时长、只提醒我 |
| 出现符合条件的空场时自动预约 | 持续监控 | 上述条件，以及明确选择自动预约 |

## 1. 安装与启动

公开版计划提供 Windows 10/11 x64 的安装版和免安装版。**目前尚无可下载的发布附件**，不需要自行搜索来历不明的安装包。

发布后应按对应版本的说明操作：

1. 从本仓库的 Releases 下载安装程序或 ZIP，并核对该版本提供的 SHA-256 校验值。
2. 安装版按向导安装；ZIP 解压到普通文件夹，不要在压缩软件内直接运行。
3. 使用安装包提供的启动入口，打开工作台。计划沿用本机地址 `http://127.0.0.1:8766/`。
4. 遇到端口占用时先查明占用程序，不要强制结束不认识的进程。
5. 首次使用先进入设置，确认测试模式和账号接入方式。

现有打包方案自带 Python；不应要求普通用户另装 Python、Git 或 Node。公开版仍需完成干净 Windows 环境验收后才能确认这一点。

没有签名或触发系统安全警告时，先核实来源与文件校验值。不要为了安装而关闭杀毒、防火墙或系统保护。

## 2. 接入自己的账号

完整配置说明见 [账号接入指南](docs/CAPTURE_SETUP.md)。需要本地 AI 帮助时，使用 [配置提示词](docs/LOCAL_AGENT_CAPTURE_PROMPT.md)。

状态判断分三步，不能只看「已连接」：

1. **页面连接或采集通道可用**：说明网页和本机工具能够通信。
2. **登录信息已同步**：说明工作台拿到了登录信息，不代表信息仍然有效。
3. **预约平台验证通过**：最近一次只读验证成功，才说明该次验证所用的登录信息有效。

优先选择你能理解并能撤销的方式：

| 方式 | 需要做什么 | 限制 |
| --- | --- | --- |
| 页面连接脚本 | 在本人已登录的官方页面执行经审核的连接脚本 | 浏览器可能不开放控制台；页面重载或连接到期后可能需要重新接入 |
| 本机采集代理 | 经本人同意配置目标域名分流、本机代理及证书 | 需要检查代理兼容性、直连例外和撤销方案，不是安装即用 |

不要把账号密码或登录信息粘贴到公开 Issue、README 或 AI 对话里。配置脚本应在使用者自己的电脑上执行，不能共用他人的证书。

## 3. 定时抢场

1. 选择运动项目，打开「定时抢场」。
2. 设置**实际使用场地的日期**、目标时段和候选场地。
3. 设置**平台开放预约的日期与时间**。它与使用日期是两个不同概念，不要混填。
4. 核对账号状态、费用条件和测试模式，再检查确认弹窗中的日期、星期和时段。
5. 确认后保持电脑开机、联网、不休眠，并保留账号恢复所需的官方页面。
6. 查看结果：预约成功、未匹配到空场、登录待恢复或结果未确认。以官方订单页为最终核对依据。

「今天 / 明天 / 后天」按设置时的日期解释，不表示任务会自动逐日滚动。跨日后核对具体日期。

现有界面的「20:00 自动切到后天并刷新」只负责场地表刷新，**不是自动创建抢场任务**。不要假设其他预约平台也在这个时间放号；公开版需要确认该选项的适用条件。

## 4. 持续监控

示例：搜索 16:00–21:00 内任意连续 1.5 小时的空场，而不是要求整个五小时全部空闲。

1. 选择日期、场地范围、搜索时段。
2. 选择「预约时长」：1、1.5 或 2 小时。
3. 选择「发现空场后」：第一次建议选**只提醒我**；选择自动预约意味着满足条件时可能直接提交真实订单。
4. 选择监控时长。即使选 24 小时，也可能因目标时段结束或其他结束条件提前停止，不表示跨日自动换目标。
5. 确认后查看任务卡片，区分正在查询、登录待恢复和已结束。

关闭浏览器不等于停止后台监控，但网页弹窗提醒需要页面开着。电脑休眠、关机或服务退出会影响任务执行。

登录失效后，现有实现会暂停查询并尝试恢复；能否恢复取决于接入方式、官方登录会话和窗口状态。需要重新登录、人工验证时，由使用者本人处理，不能承诺永久免登录。

## 5. 两种运动同时使用

现有实现为羽毛球和网球分别维护任务，但共享账号、请求预算及下单保护：

- 同一天两个运动的预约时段不能重叠。
- 同一个运动不能同时运行抢场和持续监控。
- 两个任务并不意味着可以无上限并发请求，也不保证同时预约成功。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 本机网页打不开 | 服务是否启动、8766 是否被占用；不要先修改全局代理 |
| 官方预约页面出现 502 | 本机采集代理是否运行、分流是否回环；按备份撤销本工具添加的配置 |
| 页面已连接，但平台验证失败 | 最近同步和验证时间，以及错误属于鉴权、网络还是业务问题 |
| 登录过期后没有自动刷新 | 是否启用恢复、官方页面是否还打开、登录会话是否仍有效、当前接入方式是否支持恢复 |
| 查询成功却没有预约 | 目标日期、连续时长、费用与候选场地是否满足条件；查询成功不等于存在匹配空场 |
| 提示结果未确认或存在未确认记录 | 先到官方订单页核对；不要清空记录、连续重试或创建另一任务绕过保护 |
| 关闭网页后还在监控 | 后台服务仍在运行；需要停止时先在面板中停止对应任务 |
